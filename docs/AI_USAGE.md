# AI-Assisted Development

How AI was used to build this solution, and how to reproduce the setup.

## Tools

| Tool | Use |
|---|---|
| [Claude Code](https://claude.com/claude-code) (CLI, model: Claude Opus 5.5) | Planning, test writing, refactoring, code review |

## Setup (reproducible)

1. Install Claude Code and Git (Git Bash runs the hooks on Windows).
2. Clone the repository and start `claude` **from the repository root**.
3. Everything below is committed and loads automatically. Verify with `/memory`, `/permissions`,
   `/hooks`, `/agents`.

## Configuration

| File | Purpose |
|---|---|
| `CLAUDE.md` | Project memory loaded every session: frozen contract, architecture map, commands, workflow rules. |
| `PLAN.md` | Agreed plan and decisions; the agent works one step at a time from it. |
| `.claude/settings.json` | Permissions (safe commands allowed, `git commit` asks, `git push` denied) and hooks. |
| `.claude/hooks/protect-contract.sh` | `PreToolUse`: blocks any Edit/Write to `TimeDeposit.java`. |
| `.claude/hooks/compile.sh` | `PostToolUse`: compiles after each `.java` edit; errors are fed back to the agent. |
| `.claude/hooks/run-unit-tests.sh` | `Stop`: the agent cannot finish a turn with failing unit tests. |
| `.claude/agents/test-writer.md` | Subagent: behaviour/boundary tests only, never production code. |
| `.claude/agents/architecture-reviewer.md` | Subagent: read-only diff review (hexagonal rules, SOLID, dead code, over-engineering). |
| `.claude/skills/add-plan-type/SKILL.md` | `/add-plan-type`: test-first playbook for adding an interest plan. |

Design principle: prompts and `CLAUDE.md` are guidance; hooks, tests and CI are the
enforcement. Personal overrides go in `.claude/settings.local.json` (gitignored).

## Workflow per step

Plan mode → `test-writer` adds tests → implement (hooks give feedback) → Stop hook enforces green
unit tests → `architecture-reviewer` + `/code-review` → human reviews every line → human commits.

## What was AI-assisted and why

| Area | AI involvement | Human decision / review |
|---|---|---|
| Requirements analysis & plan | Drafted by Claude from README and code | Reviewed; naming, response code and DB decisions made by the developer |

| Interest strategy refactoring (step 4) | Skeletons by Claude, failing tests by the `test-writer` subagent, then implementation; characterization tests unchanged and green | `null` plan type behaviour change decided by the developer; reviewed before commit |
| Spring Boot skeleton (step 5) | Generated by Claude; Mockito exclusion added after a dynamic-agent warning in the build | Reviewed before commit |
| Read models, ports, GET use case (step 6) | Skeletons by Claude, failing tests + in-memory fake by the `test-writer` subagent, then implementation | Reviewed before commit |
| Balance-update use case (step 7) | Skeletons by Claude; failing tests, transactional in-memory fakes and a mutation check (7 mutants incl. missing cursor, 30-day cycle, clock per chunk) by the `test-writer` subagent; implementation by Claude | Reviewed before commit |
| Schema, seed, Testcontainers setup (step 8) | Config and Flyway SQL by Claude; schema/seed/default-zone ITs by the `test-writer` subagent (pre-checked against a throwaway PostgreSQL); local run with the `local` profile verified twice (seed idempotent) | Reviewed before commit |
| Persistence read adapter (step 9) | Entities, HQL queries and adapter by Claude (HQL spike passed: no fallback needed); read ITs incl. single-statement guard by the `test-writer` subagent | Reviewed before commit |
